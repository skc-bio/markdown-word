Markdown Word · Obsidian 插件

在“页面”上写 Markdown。

Markdown Word 把 Markdown 的结构化输入、Word 的纸张概念和 PowerPoint 的自由图层放进同一条 Obsidian 工作流，并支持 PDF、PPTX、DOCX、HTML 与 Markdown 多种输出。

现在它更像什么？
  • 以 Markdown 为内容底层的分页笔记编辑器
  • 带独立图层的图文排版工具
  • 可以从同一份笔记导出 PDF / PPTX / DOCX / HTML / MD 的交付工具

它解决的核心问题

技术笔记往往同时需要“结构”和“空间”：标题、列表、公式适合 Markdown，图片、标注、图旁解释和固定分页又需要类似 Word/PPT 的视觉布局。传统工作流经常迫使你在多个软件之间重复排版。

01

Markdown 负责内容

正文、标题、列表、强调、表格和 LaTeX 继续作为可检索、可版本管理的 Markdown。

02

页面负责空间

页面有真实物理尺寸，可设置宽高、边距和基础字号，不再只是一条无限向下的文本流。

03

图层负责解释

图片、文本框、箭头、方框可以像 PPT 对象一样移动、叠放、多选与锁定。

04

PDF 负责可靠交付

推荐 PDF 保留可复制文字，并按插件中的精确页面尺寸导出。

05

公式属于文档本身

MathJax 公式无需截图；推荐的矢量 PDF 路径会针对公式字形进行处理，减少变量缺失等打印问题。

06

一份笔记，多种形态

需要演示时导 HTML/PPTX，需要打印时导 PDF，需要 Word 流式文档时导 DOCX。

与传统笔记工具相比

它并不试图彻底替代 Word、PPT 或纸笔，而是把各自最适合做笔记的部分放进同一条工作流。

导出思路

插件尽量根据不同格式的目标选择合适的表示：PDF 优先保留可复制文字和矢量公式；Office 尽量生成原生可编辑对象；视觉兼容性不足时保留 fallback；HTML 则直接保留分页展示体验。

“Markdown 负责内容，页面负责空间，图层负责解释，导出负责交付。”这比“多一个 Markdown 编辑器”更接近 Markdown Word 的目标。

推荐工作流

1. 先记用 Markdown 快速记录内容、公式和结论。
2. 再摆把图片、文本框、箭头放到最适合解释的位置。
3. 再整理调整分页、物理尺寸、边距、字号和对象层级。
4. 直接输出按需要导出 PDF / PPTX / DOCX / HTML / MD。

当前定位

Markdown Word 仍是快速迭代中的桌面插件。复杂 Office 公式、极端 CSS 样式、第三方主题和特殊字体仍可能与 Obsidian 页面存在细微差异。重要交付建议最终在目标软件中检查一次。
